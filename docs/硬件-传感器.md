# 硬件与传感器安装位置

本文核查 `docs/topic.md` 中以下话题对应的硬件来源和安装位置：

```text
/left_camera/image
/livox/imu
/livox/lidar
/points
/rgb_img
/scan
```

其中只有前三项是当前项目能够确认的真实原始传感器输入；`/rgb_img` 和 `/scan` 是算法派生数据，`/points` 的当前来源无法从仓库确认。

## 一、汇总列表

| 话题 | 硬件或来源 | 是否实体传感器 | 安装位置结论 | `frame_id` |
|---|---|---:|---|---|
| `/left_camera/image` | 海康工业相机，配置序列号 `DA7121461` | 是 | 与 MID360 刚性安装并已完成相机—雷达标定；仓库没有机械图或照片证明它在机身左侧的具体支架位置 | `camera_link` |
| `/livox/imu` | Livox MID360 内置 IMU | 是 | 位于 MID360 组件内部，不是 M20 底盘自身的 `/IMU`；相对雷达原点位置由 `T_imu_lidar` 标定 | `livox_frame` |
| `/livox/lidar` | Livox MID360 激光雷达 | 是 | 固定在 M20 机身；根据 `T_lidar_base` 反算，约在 `base_link` 前方 `0.327 m`、上方 `0.312 m`、横向接近中线 | `livox_frame` |
| `/points` | 当前来源不明 | 无法确认 | 当前 ROS 2 代码未找到有效发布链，不能映射到具体硬件或安装位置 | 无法确认 |
| `/rgb_img` | FAST-LIVO 处理 `/left_camera/image` 后的图像 | 否 | 没有独立 RGB 相机，物理来源仍是同一台海康相机 | 正常路径可能为空；回退路径继承 `camera_link` |
| `/scan` | `/cloud_registered` 经 `pointcloud_to_laserscan` 切片生成 | 否 | 没有独立 2D 雷达；它是以 `base_link` 为目标坐标系的虚拟 2D 扫描平面 | `base_link` |

## 二、海康工业相机

### 对应话题

```text
/left_camera/image
```

### 硬件信息

- 类型：海康工业相机。
- ROS 2 驱动：`mvs_ros_driver`。
- 当前配置序列号：`DA7121461`。
- 原始发布编码：`rgb8`。
- 消息类型：`sensor_msgs/msg/Image`。
- 消息坐标系：`camera_link`。

配置与发布证据：

```text
mvs_ros_driver/config/left_camera_trigger.yaml
mvs_ros_driver/src/grab_trigger.cpp
```

### 安装位置

能够确认：

- 相机和 MID360 之间是刚性安装关系。
- 项目已经配置相机与雷达的外参。
- 相机是 `/left_camera/image` 的唯一真实硬件来源。

不能确认：

- 仓库没有 M20 的 URDF、Xacro、机械尺寸图、安装照片或支架图。
- `left_camera` 只是配置和话题命名，不能仅凭名称断定相机确实安装在机器狗机身左侧。
- 无法仅凭代码可靠描述相机位于机身左前、正前或顶部的哪个支架。

当前活动外参：

```text
T_camera_lidar =
[ 0.011685  -0.999924   0.003980  -0.029332
  0.497425   0.002360  -0.867504  -0.149256
  0.867428   0.012116   0.497414   0.014702
  0          0          0          1        ]
```

来源：`config/device_parameters.yaml:26-32`。

FAST-LIVO 实际按以下方向使用：

```text
p_camera = T_camera_lidar × p_lidar
```

即代码中的数学方向是 LiDAR → Camera。YAML 的中文注释写成“camera -> lidar”，与代码实际使用方向不一致，使用时应以代码公式为准。

由该矩阵反算，相机原点在 LiDAR 坐标系中的位置约为：

```text
(0.0618, -0.0292, -0.1367) m
```

该结果只能表达两传感器原点的标定关系。没有机械图时，不应把 MID360 坐标轴直接等同于 M20 的前、左、上方向。

## 三、Livox MID360 内置 IMU

### 对应话题

```text
/livox/imu
```

### 硬件信息

- 来源：Livox MID360 内置 IMU。
- 消息类型：`sensor_msgs/msg/Imu`。
- 消息坐标系：`livox_frame`。
- 实机数据频率：约 `200 Hz`。
- 线加速度包含静止重力比力。

它不是机器狗底盘层 Domain 0 的 `/IMU`。两者是不同来源：

```text
/livox/imu：MID360 内置 IMU，供 FAST-LIVO 使用
/IMU：M20 机器狗机身主体 IMU，属于底盘反馈
```

### 安装位置

该 IMU 位于 MID360 组件内部，与雷达刚性固定。当前标定矩阵为：

```text
T_imu_lidar =
[ 1.000000  0.000000  0.000000  -0.011000
  0.000000  1.000000  0.000000  -0.023290
  0.000000  0.000000  1.000000   0.044120
  0.000000  0.000000  0.000000   1.000000 ]
```

来源：`config/device_parameters.yaml:17-24`。

FAST-LIVO 实际使用方向：

```text
p_imu = T_imu_lidar × p_lidar
```

因此 `T_imu_lidar` 的代码数学含义为 LiDAR → IMU。当前旋转为单位阵，LiDAR 原点在 IMU 坐标中的位置是：

```text
(-0.01100, -0.02329, 0.04412) m
```

反过来，IMU 原点在 LiDAR 坐标中的位置是：

```text
(0.01100, 0.02329, -0.04412) m
```

YAML 注释“IMU 到激光雷达”与代码公式相反，仿真建模和外参导入必须以代码公式为准。

## 四、Livox MID360 激光雷达

### 对应话题

```text
/livox/lidar
```

### 硬件信息

- 型号：Livox MID360。
- 消息类型：当前 Launch 配置为 `sensor_msgs/msg/PointCloud2`。
- 消息坐标系：`livox_frame`。
- 点云发布频率：约 `10 Hz`。
- 驱动：`livox_ros_driver2`。

相关配置：

```text
livox_ros_driver2/launch_ROS2/msg_MID360_launch.py
livox_ros_driver2/config/MID360_config.json
```

驱动 JSON 的设备级外参为零，说明驱动没有把点云预先变换到 `base_link` 或相机坐标系；车体安装关系由算法参数中的 `T_lidar_base` 处理。

### 安装位置

当前活动外参：

```text
T_lidar_base =
[  0.881054   0.016898  -0.472712  -0.140800
  -0.020738   0.999781  -0.002914  -0.006440
   0.472560   0.012370   0.881212  -0.430040
   0.000000   0.000000   0.000000   1.000000 ]
```

来源：`config/device_parameters.yaml:6-12`。

代码使用公式：

```text
p_lidar = T_lidar_base × p_base
T_world_base = T_world_lidar × T_lidar_base
```

即 `T_lidar_base` 严格表示 `LiDAR_T_Base`。由其逆矩阵可得 LiDAR 原点在 `base_link` 坐标中的位置约为：

```text
x =  0.327 m
y =  0.014 m
z =  0.312 m
```

如果 `base_link` 遵循 ROS REP-103：X 向前、Y 向左、Z 向上，则可以推测 MID360 安装在：

```text
机器狗车体中心前方约 32.7 cm
机器狗车体中心上方约 31.2 cm
横向偏移约 1.4 cm，接近机身中线
```

这是根据当前标定矩阵反算的安装位姿，不是机械图中的直接尺寸。若 `base_link` 轴定义不符合 REP-103，上述“前方、左侧、上方”描述需要随坐标轴定义重新解释。

### 设备数量注意事项

`MID360_config.json` 中记录了两个设备 IP，但当前 Launch 使用共享话题模式。静态仓库无法确认实机运行时是一台还是两台 MID360 在线。如果两台同时工作并共用 `/livox/lidar`，必须进一步核对：

- 两台点云是否被驱动合并到同一话题。
- 每台雷达是否有独立外参。
- 当前单一 `T_lidar_base` 是否仍然有效。

实机可通过驱动日志、设备序列号和网络连接状态确认。

## 五、`/points`

### 当前结论

```text
来源不明，不能确认为当前项目的真实硬件传感器话题。
```

`docs/topic.md` 将其记录为：

```text
/points [sensor_msgs/msg/PointCloud]
```

但当前 ROS 2 代码中没有找到 `/points` 的有效发布者或订阅者。Livox 驱动保留旧式 PCL `PointCloud` 分支，但 ROS 2 下该分支被禁用；当前主链使用的是 `sensor_msgs/msg/PointCloud2`。

因此可能性包括：

- 历史版本残留话题。
- 外部临时转换节点发布的话题。
- 旧驱动或 ROS 1 迁移遗留记录。
- 当时运行环境中的第三方节点。

运行时确认命令：

```bash
export ROS_DOMAIN_ID=42
ros2 topic info -v /points
ros2 topic type /points
ros2 topic echo /points --once
```

只有确认发布节点、消息类型和 `frame_id` 后，才能继续关联到具体硬件和安装位置。

## 六、`/rgb_img`

### 当前结论

```text
它不是第二台 RGB 相机，而是 FAST-LIVO 对 /left_camera/image 处理后的派生图像。
```

数据链：

```text
海康工业相机
  → /left_camera/image
  → FAST-LIVO 图像转换、缩放或可视化处理
  → /rgb_img
```

因此 `/rgb_img` 没有独立硬件安装位置，其物理视点仍来自同一台海康工业相机，并间接使用 `T_camera_lidar` 完成视觉与点云关系计算。

当前存在 `frame_id` 不一致：

- 回退发布路径继承输入图像 Header，通常为 `camera_link`。
- 正常 VIO 发布路径只设置时间戳，未设置 `frame_id`，因此可能为空。

运行时应使用：

```bash
export ROS_DOMAIN_ID=42
ros2 topic echo /rgb_img --once
```

检查实际 Header，不能在外部集成中假设它始终为 `camera_link`。

## 七、`/scan`

### 当前结论

```text
机器狗上没有与 /scan 一一对应的实体 2D 激光雷达。
```

它由三维点云派生：

```text
Livox MID360
  → /livox/lidar
  → FAST-LIVO
  → /cloud_registered
  → pointcloud_to_laserscan
  → /scan
```

转换配置：

```text
目标坐标系：base_link
高度范围：-0.3 m ～ 0.5 m
距离范围：0.15 m ～ 10 m
扫描范围：360°
```

配置位置：

```text
navigation/move/launch/priest_external_nav.launch.py
```

### 虚拟安装位置

`/scan` 的 `frame_id` 为 `base_link`，所以它可理解为挂在机器狗躯干坐标系上的虚拟 2D 扫描平面。它会随 `base_link` 运动，但没有独立的实体安装支架或额外外参。

其几何关系依赖：

1. MID360 的真实安装位置。
2. `T_imu_lidar`。
3. FAST-LIVO 估计的位姿。
4. `T_lidar_base`。
5. `camera_init` 到 `base_link` 的 TF。
6. `pointcloud_to_laserscan` 的高度切片范围。

因此 `/scan` 应称为“3D 点云生成的虚拟 2D LaserScan”，不应列作单独安装的 2D 雷达。

## 九、仍需现场确认的信息

仅靠仓库无法确认以下机械信息：

1. 海康相机在 M20 支架上的确切左、右、前、后位置。
2. 相机和 MID360 的实际安装照片与朝向标识。
3. `base_link` 是否严格遵循 REP-103 坐标轴定义。
4. MID360 实机实际连接数量以及两个配置 IP 的使用情况。
5. 当前外参对应哪一台具体 M20 和哪一版传感器支架。

建议现场补充：

- M20 传感器支架正视、侧视和俯视照片。
- 每个设备的型号、序列号和 IP。
- `base_link`、`livox_frame`、`camera_link` 坐标轴示意图。
- 从 `base_link` 原点测量到传感器光心或雷达原点的机械尺寸。
- 当前标定文件的机器狗 ID、标定时间和标定版本。

这些信息补齐后，才能把“矩阵反算位置”升级为可用于生产装配和跨狗兼容检查的正式硬件安装清单。
