# 需求 02：B 狗使用 A 狗地图重定位与航点操作

## 一、目标

**问：本流程要实现什么？**

答：A、B 均为 M20。A 狗已在 3 楼完成建图，平台把 A 狗生成的完整地图包部署到 B 狗；B 狗使用自身激光雷达、摄像头和 IMU，在 A 狗地图的 `map` 坐标系中确定自己的位置。定位稳定后，通过 RViz 或平台向 B 狗下发属于该地图版本的导航航点。

完整运行链路是：

```text
A 狗地图包
  -> 部署到 B 狗
  -> B 狗加载自身设备参数
  -> B 狗启动传感器和 FAST-LIVO 前端
  -> 加载 A 狗 map_3d.pcd、SC/视觉数据库、map_2d
  -> 雷达或视觉给出全局位置候选
  -> ICP 对齐并建立 map 到里程计坐标的变换
  -> /localization_status=true
  -> 启动 Nav2 和多航点管理节点
  -> /clicked_point 下发航点
  -> /global_path、/local_path
  -> /NAV_CMD
```

---

## 二、跨狗使用前的准备

**问：A 狗地图包至少包含什么？**

答：当前启用视觉融合时，B 狗的地图目录至少需要：

```text
map_3d.pcd
map_2d.pgm
map_2d.yaml
sc_database.txt
visual_descriptors.bin
orb_vocabulary.dbow3
```

这些文件必须来自 A 狗的同一次建图，不能混用不同地图版本。建议每个地图使用独立目录，例如：

```text
/home/ubuntu/robot_maps/zju_floor_3/2026.06.07-001/
```

目录路径应为绝对路径。当前部分代码通过字符串拼接文件名，传给 Launch 时应保留末尾 `/`。

**问：B 狗应该使用 A 狗还是 B 狗的设备参数？**

答：B 狗运行 FAST-LIVO 前端时应使用 **B 狗自身标定后的参数文件**。主要包括：

- `T_camera_lidar`
- `T_imu_lidar`
- `T_lidar_base`
- 摄像头内参和畸变参数
- 雷达型号及扫描参数
- IMU 噪声参数
- 图像、雷达、IMU 话题名
- 时间偏移和同步参数

A 狗的这些参数应写入地图 Manifest 作为建图来源和兼容性依据，但不能无条件覆盖 B 狗的个体标定。

**问：B 狗部署前要检查什么？**

答：至少检查：

1. A、B 都是相同硬件配置版本的 M20。
2. 雷达、摄像头、IMU 的型号、安装结构和工作模式一致。
3. B 狗已单独完成传感器标定。
4. B 狗配置中的 ROS Domain、话题名和 frame 约定正确。
5. 地图包文件完整，SHA-256 与平台 Manifest 一致。
6. `map_2d.yaml` 中 `image: map_2d.pgm`，且二者位于同一目录。
7. `sc_database.txt` 首行关键帧数大于 0。

## 三、B 狗在 GUI 中完成重定位

**问：使用控制台时，操作顺序是什么？**

答：推荐顺序如下：

1. 将 A 狗地图包部署到 B 狗的新目录，禁止覆盖正在使用的地图。
2. 在 B 狗项目根目录启动控制台：

```bash
cd /home/ubuntu/Desktop/ROS2_szs/DeepRobotics_ws
source /opt/ros/humble/setup.bash
source install/setup.bash
python3 -u robot_console/robot_console/app.py
```

3. 点击“选择设备参数配置文件”，选择 B 狗自身标定对应的参数模板。
4. 点击“设置地图存放/读取目录”，选择 A 狗地图包目录。
5. 真机操作时点击“开启传感器驱动”，确认 B 狗雷达、摄像头和 IMU 均有数据。
6. 只做 3D 重定位时点击“3D 定位”；要继续使用 Nav2 导航时点击“2D 定位”。
7. 保持 B 狗静止或缓慢改变朝向，等待雷达 Scan Context 或视觉检索给出候选，再由 ICP 完成地图对齐。
8. 观察定位状态、点云重合和 TF，确认重定位成功。
9. 需要导航时点击“2D 导航”，等待 Nav2 和多航点节点启动。
10. 启动 `rviz_slam.sh`，在地图上添加航点。

真机模式不要播放 Bag；Bag 回放只用于离线验证。

**问：为什么 B 狗需要先重定位？**

答：B 狗启动时，FAST-LIVO 只知道自身局部里程计坐标，尚不知道它在 A 狗建立的 3 楼地图中的位置。全局重定位会寻找 B 狗当前点云或图像与 A 狗历史地图的对应关系，并建立全局 `map` 坐标与 B 狗局部里程计坐标之间的变换。没有这一步，平台发送的 `map` 坐标航点无法转换为 B 狗可执行的局部运动目标。

## 四、命令行重定位流程

**问：不使用 GUI 时，怎样启动 B 狗的 2D 定位？**

答：每个终端先加载一致环境：

```bash
cd /home/ubuntu/Desktop/ROS2_szs/DeepRobotics_ws
source /opt/ros/humble/setup.bash
source install/setup.bash
export ROS_DOMAIN_ID=42
```

先启动 B 狗传感器驱动，确认以下话题存在并持续更新：

```text
/livox/lidar
/livox/imu
/left_camera/image
```

终端 1 启动 FAST-LIVO 前端，参数文件必须是 B 狗自身参数：

```bash
ros2 launch fast_livo frontend.launch.py \
  rviz:=false \
  params_file:=/home/ubuntu/Desktop/ROS2_szs/DeepRobotics_ws/config/device_parameters.yaml \
  use_sim_time:=false
```

终端 2 启动 2D 定位，地图目录替换为 A 狗地图包实际路径：

```bash
ros2 launch localization backend_localization_2d.launch.py \
  map_save_dir:=/home/ubuntu/robot_maps/zju_floor_3/2026.06.07-001/ \
  use_sim_time:=false \
  rviz:=false
```

只验证 3D 定位时可改为：

```bash
ros2 launch localization backend_localization_3d.launch.py \
  map_save_dir:=/home/ubuntu/robot_maps/zju_floor_3/2026.06.07-001/ \
  use_sim_time:=false \
  rviz:=false
```

**问：怎样判断 B 狗真正完成了重定位？**

答：不能只看 Launch 进程存在或 GUI 显示 Ready。至少检查：

```bash
ros2 topic echo /localization_status
ros2 topic echo /map_to_odom
ros2 topic hz /global_localization/cur_scan
ros2 topic hz /aft_mapped_to_init
```

同时在 RViz 中确认：

- Fixed Frame 为 `map`。
- `/map` 3D 地图已经显示。
- `/map_2d` 栅格地图已经显示。
- `/global_localization/cur_scan` 与墙面、走廊等地图结构重合。
- B 狗缓慢移动时，定位轨迹连续，没有跳到其他楼道或重复区域。
- `/localization_status` 持续为 `true`，而不是短暂闪现。

**问：自动重定位失败时怎么办？**

答：依次检查：

1. 确认 B 狗确实位于 A 狗建图覆盖范围内。
2. 将 B 狗放到结构特征明显、不是高度重复的走廊位置。
3. 保持静止完成 IMU 初始化，再缓慢旋转或移动以获得完整点云特征。
4. 检查 B 狗雷达、IMU、相机话题频率和时间戳。
5. 检查 B 狗参数中的内外参与真实设备一致。
6. 检查 `map_3d.pcd`、`sc_database.txt` 和视觉描述符来自同一地图版本。
7. 使用 RViz 的“2D Pose Estimate”工具向 `/initialpose` 发布大致初始位置和朝向，让 ICP 在附近搜索。
8. 如视觉跨狗差异明显，可暂时把 `img_en` 设为 `0`，先验证雷达 Scan Context + ICP；验证后再单独排查视觉兼容性。

手工初始位姿只是搜索提示，不代表定位已成功，仍需等待 `/localization_status=true` 并检查点云对齐。

## 五、启动导航和 RViz

**问：定位成功后怎样启动导航？**

答：GUI 中点击“2D 导航”。命令行方式为：

```bash
ros2 launch move navigation.launch.py use_sim_time:=false
```

当前导航 Launch 会延迟启动 Nav2 核心和外部导航链，多航点节点不会在命令执行瞬间立即出现。等待约 11 秒后检查：

```bash
ros2 node info /global_path_sequence_publisher
ros2 action info /compute_path_to_pose
ros2 topic info -v /clicked_point
```

然后启动独立 RViz：

```bash
cd /home/ubuntu/Desktop/ROS2_szs/DeepRobotics_ws
./rviz_slam.sh
```

脚本固定使用 `ROS_DOMAIN_ID=42` 和 `Fixed Frame=map`，预置 3D/2D 地图、当前扫描、定位轨迹、全局/局部路径、航点队列和交互式航点编辑器。

## 六、RViz 航点操作

**问：为什么之前在 RViz 中看不到 `/clicked_point`？**

答：`/clicked_point` 不是持续发布的显示话题，而是 RViz `Publish Point` 工具点击地图时临时发布的输入话题。只有启动导航中的 `global_path_sequence_publisher` 后，该话题才有订阅者；只有实际点击时才产生一条消息。因此不能通过添加普通 Display 来让它一直显示。

更新后的 `rviz_slam.sh` 已加入三个 `Publish Point` 工具：

1. `/clicked_point`：添加航点。
2. `/waypoint_sequence/delete_nearest`：删除点击位置 1.5 米内最近航点。
3. `/waypoint_sequence/replace_nearest`：把最近航点移动到点击位置。

多个同类工具在 RViz 工具栏上图标相同，应打开 `Tool Properties` 面板查看当前工具对应的 Topic，避免误操作。

**问：怎样添加导航航点？**

答：

1. 确认 2D 定位成功且导航已经启动。
2. 在 RViz 工具栏选择 Topic 为 `/clicked_point` 的 Publish Point。
3. 在 `/map_2d` 的已知自由区域单击。
4. 每次点击追加一个航点。
5. 两个点击点小于约 0.25 米时，后一个点会被忽略。
6. 节点逐段调用 `ComputePathToPose` 并发布 `/global_path`。

`clicked_point` 只有位置，没有目标朝向；当前生成的航点 yaw 通常为 0。

**问：怎样查看和编辑航点？**

答：更新后的 RViz 配置包含：

- `/waypoints_pose_array` 的 PoseArray 显示。
- `/waypoint_editor` 的 InteractiveMarkers 显示。
- `/global_path` 全局路径。
- `/local_path` 局部路径。

选择 RViz 的 `Interact` 工具后：

- 拖动航点可在 XY 平面调整位置。
- 右键航点可选择 `Delete this waypoint`。
- 右键菜单可选择 `Clear all waypoints`。
- 当前航点通常显示为橙色，已完成航点为绿色，后续航点为蓝色。

**问：`waypoint_sequence` 控制话题能直接做成 RViz 按钮吗？**

答：RViz 默认插件没有用于发布 `std_msgs/msg/Empty` 的通用按钮，所以 `clear`、`undo`、`pause`、`resume` 不能只靠 RViz 配置文件变成四个按钮。当前无需修改业务代码即可在终端执行：

```bash
ros2 topic pub --once /waypoint_sequence/pause std_msgs/msg/Empty "{}"
ros2 topic pub --once /waypoint_sequence/resume std_msgs/msg/Empty "{}"
ros2 topic pub --once /waypoint_sequence/undo std_msgs/msg/Empty "{}"
ros2 topic pub --once /waypoint_sequence/clear std_msgs/msg/Empty "{}"
```

清空操作也可以通过 Interactive Marker 右键菜单完成。如果产品需要 RViz 中固定的暂停、继续、撤销、清空按钮，需要增加自定义 RViz Panel 插件，或在 `robot_console` 中增加对应按钮。

**问：怎样查看航点状态？**

答：

```bash
ros2 topic echo /waypoint_sequence/status
ros2 topic echo /waypoints_pose_array
```

状态话题当前是字符串，常见值包括：

```text
empty
active
paused
done
```

它不是产品级任务状态，缺少目标机器狗 ID、任务 ID、地图版本、当前航点序号和结构化错误码。

## 七、当前实际话题表

| 方向 | 话题 | 类型 | 用途 |
|---|---|---|---|
| 输入 | `/clicked_point` | `geometry_msgs/msg/PointStamped` | 追加航点 |
| 输入 | `/waypoint_sequence/delete_nearest` | `geometry_msgs/msg/PointStamped` | 删除最近航点 |
| 输入 | `/waypoint_sequence/replace_nearest` | `geometry_msgs/msg/PointStamped` | 替换最近航点 |
| 输入 | `/waypoint_sequence/clear` | `std_msgs/msg/Empty` | 清空任务 |
| 输入 | `/waypoint_sequence/undo` | `std_msgs/msg/Empty` | 撤销最后航点 |
| 输入 | `/waypoint_sequence/pause` | `std_msgs/msg/Empty` | 暂停规划并清空当前路径 |
| 输入 | `/waypoint_sequence/resume` | `std_msgs/msg/Empty` | 恢复并重新规划 |
| 输出 | `/waypoint_sequence/status` | `std_msgs/msg/String` | 航点队列状态 |
| 输出 | `/waypoints_pose_array` | `geometry_msgs/msg/PoseArray` | 完整航点队列快照 |
| 输出 | `/goal_pose` | `geometry_msgs/msg/PoseStamped` | 当前执行目标 |
| 输出 | `/global_path` | `nav_msgs/msg/Path` | 多段拼接后的全局路径 |
| 协议 | `/waypoint_editor/update` | Interactive Marker 消息 | RViz 航点显示更新 |
| 协议 | `/waypoint_editor/feedback` | Interactive Marker 消息 | RViz 拖动和菜单反馈 |

`/waypoints_pose_array` 是输出快照，不是批量任务输入。平台如果需要一次下发多个航点，当前过渡方案是逐点发布 `/clicked_point`；正式产品应新增带任务 ID、地图版本和执行反馈的 Action 接口。

## 八、安全操作顺序

**问：B 狗实机执行导航前，最终检查顺序是什么？**

答：

1. 确认 B 狗加载的是平台任务绑定的 A 狗地图版本。
2. 确认 B 狗使用自身标定参数。
3. 确认传感器数据频率、时间戳和 TF 正常。
4. 确认 `/localization_status=true` 持续稳定。
5. 确认当前扫描与 3D 地图正确重合。
6. 确认 `/map_2d` 已发布且地图方向、原点正确。
7. 确认 `/compute_path_to_pose` 可用。
8. 第一次只下发近距离、低风险航点。
9. 检查 `/global_path` 未穿越墙体或未知区域。
10. 低速执行，准备急停；定位丢失时必须停止导航并输出零速度。

未经 B 狗现场重定位验证，不应直接远程下发生产导航任务。
